# Деплой в Dokploy

Dokploy сам забирает код из GitHub (ветка `main`), собирает образ по `Dockerfile` и перезапускает приложение при каждом пуше.

## Что нужно приложению

| Переменная | Обязательна | Значение |
|---|---|---|
| `MYSQL_HOST` | да | `host:port` базы, для базы в Dokploy — Internal Host и порт `3306` |
| `MYSQL_USER` | да | пользователь базы |
| `MYSQL_PASSWORD` | да | пароль пользователя |
| `MYSQL_DBNAME` | да | имя базы |
| `GIN_MODE` | нет | в образе по умолчанию `release` |
| `PORT` | нет | порт HTTP-сервера, по умолчанию `8080` |

Если обязательная переменная не задана, приложение падает при старте с `Invalid type assertion with key <NAME>`.

`config/config.yml` лежит в образе. `auth.hash_salt` оттуда нельзя менять после создания пользователей: пароли хэшируются с этой солью, и после смены никто не сможет войти.

Таблицы создаются автоматически при старте (`AutoMigrate`).

## 1. Подключить GitHub

1. Dokploy → **Settings → Git** → GitHub → **Create Github App**.
2. После создания нажать **Install**, выбрать репозиторий `kosipov/students` → **Install & Authorize**.

## 2. Создать проект и базу

1. **Create Project**, например `students`.
2. В проекте **Create Service → Database → MySQL**. Образ `mysql:8.0`: с ним приложение проверено.
3. Задать Database Name, User, Password → **Deploy**.
4. Со страницы базы понадобится **Internal Host** (для `MYSQL_HOST`). **External Port** не открывать: приложению он не нужен.
5. Настроить бэкапы: **Settings → Destinations** (S3-бакет), затем на странице базы **Backups**: destination, cron, например `0 3 * * *`. Нажать **Test** и убедиться, что файл появился в бакете.

## 3. Создать приложение

В том же проекте **Create Service → Application**.

**General → Provider: GitHub**
- Repository: `kosipov/students`
- Branch: `main`
- Build Path: `/`

**Build Type: Dockerfile**
- Docker File: `Dockerfile`
- Docker Context Path: `.`
- Docker Build Stage: пусто (нужен последний этап)

**Environment** — переменные из таблицы выше, например:

```
MYSQL_HOST=<Internal Host базы>:3306
MYSQL_USER=<user>
MYSQL_PASSWORD=<password>
MYSQL_DBNAME=<database>
```

**Advanced → Cluster Settings → Swarm Settings**

- **Health Check** — оставить пустым. В образе уже есть `HEALTHCHECK` на `/healthz` через `wget`, Swarm использует его. Пример из документации Dokploy с `curl` здесь не подойдёт: `curl` в образе нет. Если нужно задать явно:

  ```json
  {
    "Test": ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1:8080/healthz || exit 1"],
    "Interval": 15000000000,
    "Timeout": 3000000000,
    "StartPeriod": 10000000000,
    "Retries": 3
  }
  ```

- **Update Config** — сначала поднимать новый контейнер, и только когда он станет healthy, гасить старый. Если новый не поднялся, откатываться:

  ```json
  {
    "Parallelism": 1,
    "Delay": 5000000000,
    "FailureAction": "rollback",
    "Monitor": 20000000000,
    "Order": "start-first"
  }
  ```

Replicas: `1`. Приложение хранит сессии в cookie, так что несколько реплик тоже будут работать, но пока в этом нет необходимости.

Нажать **Deploy** и проверить в **Deployments**, что сборка прошла, а в **Logs** — что приложение стартовало без ошибок.

## 4. Домен

1. Сначала проверить на временном домене: **Domains → traefik.me** (только HTTP), Container Port `8080`.
2. Боевой домен: A-запись `student.kosipov.ru` → IP сервера Dokploy (и `www.student.kosipov.ru`, если нужен).
3. **Domains → Add Domain**: Host `student.kosipov.ru`, Path `/`, Container Port `8080`, HTTPS включён, Certificate `letsencrypt`.

Сертификат выпускается, когда DNS уже указывает на сервер Dokploy. Порты 80 и 443 на сервере должны быть открыты.

## 5. Первый администратор

Регистрации в приложении нет, пользователь создаётся командой в контейнере приложения.

Через терминал контейнера в Dokploy:

```sh
./create-admin -username admin
```

Или по SSH на сервере Dokploy:

```sh
docker exec -it $(docker ps -q -f name=<appName> | head -n1) ./create-admin -username admin
```

`<appName>` — App Name приложения в Dokploy.

Пароль спрашивается без отображения ввода (не короче 8 символов). Команда откажет, если пользователь с таким логином уже есть.

## 6. Проверка

- `https://student.kosipov.ru/healthz` → `200`
- главная открывается, стили и шрифты подгружены
- вход на `/login`, в управлении: создание, изменение, скрытие и удаление группы, предмета и задания
- пуш в `main` запускает новый деплой (**Deployments**)

## Как устроено приложение

- `web/` — фронтенд (React + TypeScript, сборка Vite). В образе собирается в `web/dist`, Go-сервер отдаёт его для всех адресов, кроме `/api/*`, `/assets/*` и `/healthz`.
- `/api/*` — JSON API. Изменяющие запросы должны содержать заголовок `X-Requested-With: fetch` (защита от CSRF), управление (`/api/admin/*`) доступно только после входа.

## «Где меня найти» по расписанию университета

- На главной показывается, где преподаватель сейчас по расписанию на campus.syktsu.ru: на паре (аудитория, корпус, до какого времени), перерыв между парами или «в университете нет» с первой парой, оставшейся на сегодня.
- У кампуса нет API: сервер раз в 30 минут открывает страницу расписания преподавателя, как браузер (текущая и следующая неделя, два запроса), и копирует занятия в базу. Сайт отвечает из базы и не зависит от доступности кампуса.
- ФИО и интервал — в `config/config.yml` (`campus.teacher`, `campus.sync_interval`, не меньше 5 минут). Пустое ФИО выключает функцию.
- Если кампус недоступен или страница изменилась, старые занятия остаются, ошибка видна в «Обзоре» и в логе: `Failed to sync schedule`. Там же кнопка «Обновить сейчас» (не чаще раза в минуту). Если расписание не обновлялось больше 6 часов, на главной появляется предупреждение.
- Пары считаются по 90 минут, время — московское. Если кампус изменит вёрстку страницы, разбор в `campus/parser.go` сверяется с сохранёнными страницами в `campus/testdata`.

### Если кампус не отвечает серверу (прокси)

Кампус может не отвечать на запросы с адреса сервера: в логе тогда `context deadline exceeded (Client.Timeout exceeded while awaiting headers)` при каждой попытке. Проверить с сервера:

```sh
curl -s -o /dev/null -m 60 -X POST --data-urlencode 'name=Осипов Константин Сергеевич' \
  -w 'HTTP %{http_code} connect=%{time_connect}s ttfb=%{time_starttransfer}s\n' \
  https://campus.syktsu.ru/schedule/teacher/
```

Если соединение устанавливается, а ответа нет, нужен посредник с российским адресом. Рекомендуемый способ — функция в Yandex Cloud: бесплатного уровня (1 млн вызовов в месяц) хватает с огромным запасом, нам нужно около 3 000.

**1. Создать функцию**

1. В [Yandex Cloud](https://console.yandex.cloud) создайте платёжный аккаунт (физлицу нужно привязать карту, при проверке ненадолго блокируется небольшая сумма).
2. **Cloud Functions → Создать функцию**, имя `campus-relay`.
3. **Создать версию:**
   - среда выполнения **Python 3.12**, способ — редактор кода;
   - файл `index.py` — содержимое [`deploy/campus-relay/index.py`](deploy/campus-relay/index.py);
   - точка входа `index.handler`, таймаут **30** секунд, память 128 МБ;
   - переменная окружения `RELAY_SECRET` — длинная случайная строка, получить можно командой `openssl rand -hex 24`.
4. На вкладке **Обзор** включите **Публичная функция** и скопируйте **ссылку для вызова** вида `https://functions.yandexcloud.net/d4e…`.

**2. Подключить к сайту**

В Dokploy добавьте переменные окружения приложения и передеплойте:

```
CAMPUS_RELAY_URL=https://functions.yandexcloud.net/d4e…
CAMPUS_RELAY_SECRET=то же значение, что RELAY_SECRET
```

**3. Проверить**

- В логе приложения: `Campus schedule is requested through relay https://functions.yandexcloud.net/…`.
- В «Обзоре» админки в блоке «Расписание университета» появится свежее «Обновлено …» без строки об ошибке. Можно не ждать полчаса, а нажать «Обновить сейчас».
- Если секрет не совпадает, в ошибке будет `unexpected status 403`; если функция не смогла достучаться до кампуса — `504`.

Замечания:
- Функция публичная, но отвечает только тем, кто знает секрет, и ходит единственным POST-запросом на адрес из `CAMPUS_URL`. Открытым прокси она не становится.
- Сменить секрет — поменять его в двух местах: в переменных функции и в переменных Dokploy.
- Если функция перестанет работать, сайт продолжит показывать последнее известное расписание, а ошибка будет видна в «Обзоре».

**Альтернатива — обычный прокси.** Вместо посредника можно указать прокси с российским адресом:

```
CAMPUS_PROXY_URL=http://логин:пароль@адрес-прокси:3128
```

Поддерживаются `http://`, `https://` и `socks5://`. Через прокси идут **только** запросы к кампусу, OneDrive и остальное — напрямую. При ошибке в адресе приложение не стартует и пишет, что не так; пароль прокси в логи не попадает. Бесплатные публичные прокси не советую: они ненадёжны и часто сами заблокированы.

## Задания с паролем

- Пароль задаётся в форме задания и виден в управлении, поэтому хранится в базе как есть. Это код доступа к заданию — не используйте пароли от своих аккаунтов.
- Без пароля студент видит название и пояснение, но не текст задания и не ссылку на файл. Введённый пароль запоминается в браузере студента, пока пароль задания не сменят.
- Пароль закрывает ссылку только на сайте: если ссылка на файл в OneDrive попала к студенту другим путём, она откроется и без пароля.
- Подбор ограничен: 10 неверных попыток за 15 минут с одного адреса и 100 на задание суммарно. Неудачные попытки пишутся в лог: `Wrong password for task`.
- Адрес студента берётся из `X-Forwarded-For`, который добавляет Traefik. **Не публикуйте порт 8080 контейнера наружу** (Advanced → Ports в Dokploy должны быть пустыми), иначе заголовок можно подделать в обход Traefik.

Локальная разработка:

```sh
go run ./cmd/api            # API на :8080, нужны MYSQL_* переменные
cd web && npm install && npm run dev   # фронтенд на :5173, /api проксируется на :8080
cd web && npm test          # тесты фронтенда
go test ./...               # тесты бэкенда
```

## Задания из OneDrive

Ссылки на markdown-файлы в OneDrive (`1drv.ms`, `onedrive.live.com`) открываются на сайте как страница `/tasks/:id`, остальные ссылки — как есть. Настраивать ничего не нужно, приложению нужен только исходящий HTTPS к `api-badgerp.svc.ms` и `api.onedrive.com`.

- Файл скачивается в фоне при создании задания или смене ссылки. Копия хранится в базе и проверяется на изменения не чаще раза в 5 минут.
- Загрузка идёт через недокументированный API, которым пользуется веб-версия OneDrive, поэтому Microsoft может его сломать. Тогда студенты продолжат видеть последние скачанные версии.
- Статус загрузки и ошибка видны в админке у каждого задания, кнопка «Обновить» скачивает файл заново. Ошибки также пишутся в лог: `Failed to fetch content of subject object`.

## Откат

- Сборка упала — старый контейнер продолжает работать, ничего делать не нужно.
- Новый контейнер не стал healthy — Swarm откатится сам (`FailureAction: rollback`).
- Ошибка в коде, которая проявилась позже, — `git revert` проблемного коммита и пуш в `main`.

# Деплой

Прод — `student.kosipov.ru` на сервере `kosipov.ru`. Развёртывание делает Ansible
из отдельного репозитория инфраструктуры `kosipov_ru_server` (роль `student`);
Dokploy больше не используется. Справочная копия роли лежит в
[`deploy/ansible/`](deploy/ansible/) — источник истины в серверном репозитории.

## Как выкатить новую версию

```sh
git push origin main                                    # из этого репозитория
cd ~/Site/pet-projects/kosipov_ru_server/ansible        # репозиторий инфраструктуры
ansible-playbook playbooks/site.yml --tags student
```

Роль `student` клонирует `main` в `/opt/src/students` на сервере, раскладывает
`/opt/students/.env` и `docker-compose.yml` из шаблонов, собирает образ по
`Dockerfile` (`build: always` — пересборка при каждом прогоне) и перезапускает
контейнер `students`. Нулевого даунтайма нет: контейнер один, пересборка
занимает пару минут, сайт в это время недоступен.

HTTPS и маршрутизацию делает Traefik (отдельная роль) по лейблам из
`docker-compose.yml`; приложение слушает только HTTP :8080 во внутренней
docker-сети `web` и наружу портом не опубликовано.

## Что нужно приложению

Переменные окружения (на проде подставляются в `.env` из ansible-шаблона
`env.j2`, секреты — из ansible-vault):

| Переменная | Обязательна | Значение |
|---|---|---|
| `MYSQL_HOST` | да | хост общего MySQL-контейнера (`mysql`) |
| `MYSQL_USER` / `MYSQL_PASSWORD` | да | доступ к базе |
| `MYSQL_DBNAME` | да | `students` |
| `CAMPUS_RELAY_URL` / `CAMPUS_RELAY_SECRET` | да (для кампуса) | адрес и секрет релея, см. ниже |
| `CAMPUS_PROXY_URL` | нет | альтернатива релею: `http://user:pass@host:3128` или `socks5://…` |
| `GIN_MODE` | нет | в образе по умолчанию `release` |
| `PORT` | нет | порт HTTP-сервера, по умолчанию `8080` |

Если обязательная переменная не задана, приложение падает при старте с
`Invalid type assertion with key <NAME>`.

`config/config.yml` лежит в образе. `auth.hash_salt` оттуда нельзя менять после
создания пользователей: пароли хэшируются с этой солью, и после смены никто не
сможет войти. Там же живут `campus.teacher` (ФИО для «где меня найти»; пустое
значение выключает функцию) и `campus.sync_interval` (сейчас `6h`, минимум 5 минут).

Таблицы создаются автоматически при старте (`AutoMigrate`).

## Первый администратор

Регистрации в приложении нет, пользователь создаётся командой в контейнере:

```sh
docker exec -it students ./create-admin -username admin
```

Пароль спрашивается без отображения ввода (не короче 8 символов) или читается
из `ADMIN_PASSWORD`. Команда откажет, если пользователь с таким логином уже есть.

## Проверка после деплоя

- `https://student.kosipov.ru/healthz` → `200`
- главная открывается, стили и шрифты подгружены
- вход на `/login`, в управлении: группы/предметы/задания, «Обзор» показывает
  свежую синхронизацию расписания, `/admin/labs` отдаёт занятость аудиторий
- логи контейнера: Dozzle на `monitor.kosipov.ru` или `docker logs students`

## Как устроено приложение

- `web/` — фронтенд (React + TypeScript, сборка Vite). В образе собирается в
  `web/dist`, Go-сервер отдаёт его для всех адресов, кроме `/api/*`, `/assets/*`
  и `/healthz`.
- `/api/*` — JSON API. Изменяющие запросы должны содержать заголовок
  `X-Requested-With: fetch` (защита от CSRF), управление (`/api/admin/*`)
  доступно только после входа.

## «Где меня найти» и лаборатории по расписанию университета

- На главной показывается, где преподаватель сейчас по расписанию на
  campus.syktsu.ru: на паре (аудитория, корпус, до какого времени), перерыв
  между парами или «в университете нет» с первой парой, оставшейся на сегодня.
- У кампуса нет API: сервер раз в 6 часов открывает страницу расписания
  преподавателя, как браузер (текущая и следующая неделя, два запроса с паузой),
  и копирует занятия в базу. Сайт отвечает из базы и не зависит от доступности
  кампуса.
- В админке («Лаборатории») — занятость компьютерных аудиторий 2 и 5 этажа по
  этажу, дате и паре: сервер запрашивает страницы аудиторий кампуса и кэширует
  их на 12 часов; кампус показывает текущую неделю и три следующие. Кнопка
  «Запросить с кампуса» у аудитории сбрасывает её кэш. Эндпоинты:
  `GET /api/admin/labs?floor=2|5|all&date=YYYY-MM-DD&pair=now|1..8` и
  `POST /api/admin/labs/refresh`.
- Если кампус недоступен или страница изменилась, старые занятия остаются,
  ошибка видна в «Обзоре» и в логе: `Failed to sync schedule`. Там же кнопка
  «Обновить сейчас» (не чаще раза в минуту). Если расписание не обновлялось
  больше 6 часов, на главной появляется предупреждение.
- Пары считаются по 90 минут, время — московское. Если кампус изменит вёрстку
  страницы, разбор в `campus/parser.go` и `campus/rooms.go` сверяется с
  сохранёнными страницами в `campus/testdata`.

### Релей кампуса

Кампус не отвечает на запросы с адреса сервера (в логе — `context deadline
exceeded` при каждой попытке), поэтому сайт ходит через посредника с российским
адресом.

**Основной способ — контейнер на Cloud.ru Evolution Container Apps.**
Код: [`deploy/campus-relay/main.go`](deploy/campus-relay/main.go) + `Dockerfile`
(образ ~10 МБ). Платформа открыта физлицам (console.cloud.ru, в т.ч. по Сбер ID),
бесплатного месячного лимита Container Apps хватает с огромным запасом.

1. Образ собирается GitHub Actions
   ([`.github/workflows/campus-relay.yml`](.github/workflows/campus-relay.yml))
   при изменении `deploy/campus-relay/**` и пушится в два реестра:
   `ghcr.io/kosipov/campus-relay` (источник правды, пакет public) и Evolution
   Artifact Registry — Container Apps умеет тянуть образы только оттуда. Для
   пуша в Cloud.ru в секретах репозитория (Settings → Secrets and variables →
   Actions) должны быть `CLOUDRU_REGISTRY`, `CLOUDRU_KEY_ID`, `CLOUDRU_KEY_SECRET`.
2. Приложение в Evolution Container Apps создано из образа
   `<реестр>/campus-relay:latest`: порт `8080`, переменная `RELAY_SECRET`,
   минимум экземпляров **0** (scale-to-zero), публичный доступ. Холодный старт
   тянет свежий `latest` сам; если контейнер был тёплым, пересоздайте ревизию
   после обновления образа.
3. Публичный URL приложения задан в ansible-переменной `campus_relay_url`
   (group_vars серверного репозитория), секрет — в vault
   (`vault_campus_relay_secret`); после смены — прогнать роль `student`.
4. Проверка:

   ```sh
   curl -X POST -H 'X-Relay-Secret: …' --data-urlencode 'name=Фамилия И. О.' <URL>/        # расписание преподавателя
   curl -X POST -H 'X-Relay-Secret: …' -H 'X-Relay-Target: classroom' \
        --data-urlencode 'num_aud=245/1' --data-urlencode 'searchdata=' <URL>/               # расписание аудитории
   ```

**Запасной способ — функция в Yandex Cloud.** Тот же протокол, код —
[`deploy/campus-relay/index.py`](deploy/campus-relay/index.py): Python 3.12,
точка входа `index.handler`, таймаут 30 с, память 128 МБ, переменная
`RELAY_SECRET`, публичный доступ. URL функции подставляется в `CAMPUS_RELAY_URL`.
Бесплатного уровня (1 млн вызовов в месяц) хватает с запасом.

Замечания по обоим вариантам:

- Релей публичный, но отвечает только тем, кто знает секрет, и ходит единственным
  POST-запросом на три адреса кампуса: расписание преподавателя (`CAMPUS_URL`),
  список студентов группы (`CAMPUS_STUDENTS_URL`) и расписание аудитории
  (`CAMPUS_CLASSROOM_URL`); адрес выбирается заголовком `X-Relay-Target`
  (`students`, `classroom`, иначе — расписание). Открытым прокси он не является.
- Если релей развёрнут давно, обновите его код: версия без цели `classroom` не
  умеет расписание аудиторий, и лаборатории через неё не заработают.
- Сменить секрет — поменять его в двух местах: в переменных релея и в vault
  ansible, затем прогнать роль `student`.
- Если релей перестанет работать, сайт продолжит показывать последнее известное
  расписание, а ошибка будет видна в «Обзоре».

**Альтернатива — обычный прокси.** Вместо посредника можно указать прокси с
российским адресом:

```
CAMPUS_PROXY_URL=http://логин:пароль@адрес-прокси:3128
```

Поддерживаются `http://`, `https://` и `socks5://`. Через прокси идут **только**
запросы к кампусу, OneDrive и остальное — напрямую. При ошибке в адресе
приложение не стартует и пишет, что не так; пароль прокси в логи не попадает.
Бесплатные публичные прокси не советую: они ненадёжны и часто сами заблокированы.

## Задания с паролем

- Пароль задаётся в форме задания и виден в управлении, поэтому хранится в базе
  как есть. Это код доступа к заданию — не используйте пароли от своих аккаунтов.
- Без пароля студент видит название и пояснение, но не текст задания и не ссылку
  на файл. Введённый пароль запоминается в браузере студента, пока пароль задания
  не сменят.
- Пароль закрывает ссылку только на сайте: если ссылка на файл в OneDrive попала
  к студенту другим путём, она откроется и без пароля.
- Подбор ограничен: 10 неверных попыток за 15 минут с одного адреса и 100 на
  задание суммарно. Неудачные попытки пишутся в лог: `Wrong password for task`.
- Адрес студента берётся из `X-Forwarded-For`, который добавляет Traefik.
  Порт 8080 контейнера наружу не публикуется (в compose нет `ports:`), поэтому
  заголовок подделать нельзя; не добавляйте публикацию порта.

## Задания из OneDrive

Ссылки на markdown-файлы в OneDrive (`1drv.ms`, `onedrive.live.com`) открываются
на сайте как страница `/tasks/:id`, остальные ссылки — как есть. Настраивать
ничего не нужно, приложению нужен только исходящий HTTPS к `api-badgerp.svc.ms`
и `api.onedrive.com`.

- Файл скачивается в фоне при создании задания или смене ссылки. Копия хранится
  в базе и проверяется на изменения не чаще раза в 5 минут.
- Загрузка идёт через недокументированный API, которым пользуется веб-версия
  OneDrive, поэтому Microsoft может его сломать. Тогда студенты продолжат видеть
  последние скачанные версии.
- Статус загрузки и ошибка видны в админке у каждого задания, кнопка «Обновить»
  скачивает файл заново. Ошибки также пишутся в лог: `Failed to fetch content of
  subject object`.

## Откат

- Контейнер не поднялся после деплоя — старый уже остановлен; быстрый откат:
  `git revert` проблемного коммита, пуш в `main` и повторный прогон роли
  `student` (пересборка займет те же пару минут).
- База не трогается: схема только расширяется через `AutoMigrate`, откат кода
  с лишними колонками безопасен.

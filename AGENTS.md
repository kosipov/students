# AGENTS.md

Сайт преподавателя: Go-монолит (API + статика SPA) + React-фронтенд в `web/` + MySQL.
Что система делает и как устроена — `README.md`; как выкатывается — `DEPLOY.md`.

## Команды

- Бэкенд: `go build ./...`, `go test ./...`, форматирование — `gofmt` (CI нет, проверяй локально).
- Фронтенд (в `web/`): `npm run typecheck`, `npm test`, `npm run build`.
  `npm run build` включает `tsc --noEmit` — типы проверяются сборкой.
- Прогоняй оба слоя перед коммитом, даже если менял только один.

## Стиль кода

- Комментарии в коде — на английском, и они объясняют *почему*, а не *что*
  (см. существующие файлы `campus/`, `schedule/`). Весь пользовательский текст
  (API-ошибки, UI) — на русском.
- Новые возможности — новый доменный пакет на верхнем уровне (`auth`, `labs`,
  `progress`…), а не рост существующего. Внутри пакета слои:
  `delivery/http` (тонкие хендлеры, перевод HTTP ↔ домен) → `usecase` (логика) →
  `repository/gorm` (только если есть таблицы). Посмотри на `labs/` как на
  эталон маленького пакета и на `educational/` — большого.
- Маршруты регистрируются в `server/app.go`: публичные в группу `api`,
  админские — в группу `admin` (она уже под auth-middleware).
- База: gorm v1 (`github.com/jinzhu/gorm`), новая таблица = модель в `models/`
  + строка в `AutoMigrate` в `server/app.go`. Файловых миграций нет.
- Фронтенд: запросы только через хуки в `web/src/api/queries.ts`, типы ответов —
  в `web/src/api/types.ts`. Стили — переиспользование существующих классов
  (`panel`, `panel-row`, `btn`, `tag-*`, `chips`); новые классы добавляй в
  `web/src/styles/app.css` рядом с похожими.

## Кампус — главный источник тонкостей

`campus.syktsu.ru` — HTML-сайт без API, и он *хрупкий и чужой*. Правила:

- **Бережливость**: паузы между запросами (`requestPause`), ограниченная
  параллельность, кэш лабораторий 12 ч. Любая новая фича, ходящая в кампус,
  обязана кэшировать ответы — ддосить вузовский сайт нельзя.
- **Парсеры защищены контрактными тестами**: тесты парсят реальные сохранённые
  страницы из `campus/testdata/`. Меняешь парсер — сначала сохрани свежую
  страницу в `testdata` (curl с обычным браузерным User-Agent), потом пиши тест
  на ней. Если сайт вуза вернул непохожую страницу — это `ErrUnexpectedPage`,
  и старые данные в базе не затираются.
- **Время**: вуз живёт в MSK круглый год, это `campus.Location` (фиксированная
  зона, без tzdata). Все даты/время расписания считай через неё; на фронтенде —
  хелперы с `timeZone: 'Europe/Moscow'` (см. `web/src/lib/presence.ts`,
  `web/src/lib/labs.ts`).
- **Релей/прокси**: прод не может достучаться до кампуса напрямую. Новый запрос
  к кампусу = новый `X-Relay-Target` в `deploy/campus-relay/main.go` *и*
  `index.py` (два релея живут параллельно, держи их в синхроне), иначе в проде
  фича молча не заработает.

## Тесты

- Go: табличные тесты, httptest-серверы для HTTP-клиентов; время и TTL в
  юзкейсах подменяются через неэкспортируемые поля (`now`, `ttl`) — тесты в том
  же пакете.
- Фронтенд: `renderWithProviders` + `mockApi` из `web/src/test/render.tsx`;
  URL в ключах mockApi сравнивается точно, включая query-строку.

## Деплой и секреты

- Деплой = пуш в `main`, затем `ansible-playbook playbooks/site.yml --tags student`
  из серверного репозитория (пример роли — `deploy/ansible/`). Образ релея
  собирает GitHub Actions при изменении `deploy/campus-relay/**`.
  Какой релей активен, решает `CAMPUS_RELAY_PROVIDER` в `.env` (без редеплоя),
  запасное значение — `campus.relay` в `config.yml` (`yandex` по умолчанию);
  адреса — в env `CAMPUS_RELAY_URL_<ПРОВАЙДЕР>`.
- Секреты только через env (`MYSQL_*`, `CAMPUS_RELAY_*`); в репозитории их нет
  и быть не должно. `config/config.yml` в образе менять нельзя после создания
  пользователей (соль паролей).

# students

Сайт преподавателя для студентов: задания с файлами, «где меня найти» по расписанию
университета, успеваемость и занятость компьютерных лабораторий.
Боевой адрес — https://student.kosipov.ru.

## Что умеет

**Для студентов (публично, без входа):**

- Каталог групп → предметов → заданий. Тексты заданий — markdown-файлы из OneDrive,
  скачанные сервером и отданные как красивые страницы.
- Задания с паролем: студент видит название, а текст и файл открываются после ввода
  кода доступа (подбор ограничен по попыткам).
- «Где меня найти»: на главной показано, где преподаватель сейчас по расписанию
  campus.syktsu.ru — на паре (аудитория, до скольки), на перемене или вне университета.
- Успеваемость: ведомости по группам и личная страница студента с оценками.

**Для преподавателя (админка, один пользователь):**

- Управление группами, предметами, заданиями; импорт списка студентов группы
  прямо из кампуса вуза.
- Журнал оценок (матрица студенты × задания).
- Состояние синхронизации расписания + кнопка «Обновить сейчас».
- Занятость лабораторий (2 и 5 этаж): по этажу, дате и паре видно, кто сидит
  в каждой аудитории; данные кампуса кэшируются на 12 часов, любую аудиторию
  можно принудительно перезапросить.

## Архитектура

Монолит на Go, который отдаёт JSON API и статику собранного фронтенда.
Один бинарь, одна база MySQL, никаких очередей и фоновых воркеров, кроме
таймера синхронизации расписания.

```
Браузер (React SPA)  ──►  Go API (gin)  ──►  MySQL
                               │
                               ├──► campus.syktsu.ru   (через релей, HTML-парсинг форм)
                               └──► OneDrive            (скачивание файлов заданий)
```

- **Фронтенд** — React 19 + TypeScript + Vite, живёт в `web/`. В проде собирается
  в `web/dist` внутри Docker-образа и раздаётся тем же Go-процессом (SPA-fallback
  на `index.html` для всех путей, кроме `/api/*` и `/healthz`).
- **Бэкенд** — Go, gin, сессия админа в подписанной cookie. Изменяющие запросы
  требуют заголовок `X-Requested-With: fetch` (CSRF-защита), всё управление
  (`/api/admin/*`) — только после входа.
- **База** — MySQL 8, схема создаётся сама при старте (`AutoMigrate`), миграций
  как отдельных файлов нет.

### Внешние зависимости

| Сервис | Зачем | Как ходим |
|---|---|---|
| `campus.syktsu.ru` | расписание преподавателя, списки групп, занятость аудиторий | API у сайта нет: POST-им формы, как браузер, и парсим HTML. Раз в 6 часов фоновая синхронизация расписания в базу; лаборатории — по запросу админа с кэшем 12 ч |
| Релей кампуса (`CAMPUS_RELAY_URL`) | вузовский сайт не отвечает на адрес нашего сервера | крошечный контейнер на Cloud.ru Evolution (`deploy/campus-relay/`), запасной вариант — функция Yandex Cloud (`index.py` там же). Не открытый прокси: только три адреса кампуса, только с секретом. Вместо релея можно указать обычный прокси (`CAMPUS_PROXY_URL`) |
| OneDrive | файлы заданий | недокументированный API веб-версии; скачанная копия хранится в базе, поэтому падение OneDrive не ломает сайт |
| MySQL | все данные | единственная обязательная зависимость при старте |

### Разделение по папкам

Код делится на доменные пакеты; внутри пакета слои `delivery/http` → `usecase` →
`repository/gorm` (вдохновлено clean architecture, без фанатизма).

| Папка | Ответственность |
|---|---|
| `cmd/api` | точка входа сервера |
| `cmd/createadmin` | создание первого администратора (запускается в контейнере) |
| `server` | сборка приложения: gin, middleware, маршруты, подключение MySQL, фоновая синхронизация |
| `models` | gorm-модели таблиц |
| `auth` | вход админа, middleware авторизации |
| `educational` | группы, предметы, задания, каталог для студентов |
| `progress` | студенты групп и оценки |
| `schedule` | расписание преподавателя в базе + «где я сейчас» |
| `labs` | занятость лабораторий: список аудиторий, кэш на 12 ч, расписание пар |
| `campus` | клиент кампуса: формы, парсеры HTML, прокси/релей; тесты сверяются с сохранёнными страницами в `campus/testdata` |
| `onedrive` | скачивание файлов заданий |
| `markdown` | рендер markdown-заданий в HTML |
| `web` | фронтенд (`src/pages`, `src/api`, `src/components`, `src/lib`) |
| `deploy` | релей кампуса и ansible-пример выкатки (`deploy/ansible`) |
| `config` | `config.yml`: порт, соль паролей, ФИО преподавателя, интервал синхронизации |

Тесты: Go — рядом с кодом (`*_test.go`); фронтенд — vitest + testing-library,
моки API через `web/src/test/render.tsx`.

## Локальный запуск

Нужны Go, Node.js и MySQL 8 (достаточно `docker run -p 3306:3306 -e MYSQL_ROOT_PASSWORD=... mysql:8`).

```sh
export MYSQL_HOST=127.0.0.1:3306 MYSQL_USER=root MYSQL_PASSWORD=... MYSQL_DBNAME=students
go run ./cmd/api                 # API на :8080, таблицы создадутся сами

cd web && npm ci && npm run dev  # фронтенд на :5173, /api проксируется на :8080
```

Создать администратора локально: `ADMIN_PASSWORD=... go run ./cmd/createadmin -username admin`
(без переменной пароль спросит интерактивно).

Тесты: `go test ./...` и `cd web && npm test` (+ `npm run typecheck`).

Кампус с локальной машины обычно отвечает напрямую; если нет — задайте
`CAMPUS_RELAY_URL`/`CAMPUS_RELAY_SECRET` или `CAMPUS_PROXY_URL` (см. DEPLOY.md).

## Запуск на другом сервере

Минимальный путь — Docker:

```sh
docker build -t students .
docker run -p 8080:8080 \
  -e MYSQL_HOST=... -e MYSQL_USER=... -e MYSQL_PASSWORD=... -e MYSQL_DBNAME=students \
  students
```

Образ сам собирает фронтенд и два бинаря (`student-app`, `create-admin`),
конфиг `config/config.yml` лежит внутри. Перед приложением нужен любой
reverse proxy с HTTPS (на боевом сервере — Traefik по лейблам compose-файла).

Боевая выкатка автоматизирована ansible-ролью из отдельного репозитория
инфраструктуры; её копия-пример лежит в `deploy/ansible/`. Подробности —
переменные, релей, первый админ, откат — в [DEPLOY.md](DEPLOY.md).
